# MindScope 开发者文档

> 适用版本：0.7.0。面向想要阅读、修改或发布 MindScope 的开发者。产品需求见 `docs/phase0/PHASE0_方案.md`，各阶段决策见 `docs/phaseN/`。

## 1. 原则

1. **离线优先**：默认零网络请求。唯一的联网功能（可选 AI、在浏览器打开链接）必须由用户触发并确认。
2. **白盒、可复现**：评分公式、题库、选题逻辑公开；同一份答案永远得到同一个结果（选题器用固定种子）。
3. **不写 C 盘**：桌面版所有文件都在 exe 所在文件夹（或用户指定的数据目录）下，包括 WebView2 的浏览器数据。
4. **不诊断**：人格结果不推断心理状态；心理自评只是筛查，触发安全题时固定显示求助资源。
5. **两端同一套逻辑**：评分、选题、SQL 都在共享的 TypeScript 包里，网页与桌面只在"平台层"不同。

## 2. 技术栈

| 层 | 技术 |
|---|---|
| 桌面外壳 | Tauri 2（Rust）+ Microsoft Edge WebView2 |
| 界面 | Vue 3 + TypeScript 5.9 + Vite + Naive UI + Pinia + vue-router（hash 模式）+ vue-i18n |
| 图表 | Apache ECharts 6（SVG 渲染，打印清晰） |
| 数据库 | SQLite：网页用 `@sqlite.org/sqlite-wasm`（Worker + OPFS `opfs-sahpool`）；桌面用 `rusqlite`（bundled）；测试用 Node 的 `node:sqlite` |
| PDF | WebView2 `PrintToPdf`（桌面），浏览器打印（网页） |
| AI（可选） | Rust `reqwest`（Windows schannel TLS）+ OpenAI 兼容接口；Key 用 DPAPI 加密 |
| 测试 | Vitest、Playwright（系统 Edge）、`cargo test`、PowerShell 发布测试 |

## 4. 架构

```
Vue 页面 ─► Pinia store ─► Repositories (@mindscope/storage) ─► SqlDriver
                                                                 ├─ web:     Worker 中的 sqlite-wasm（OPFS）
                                                                 └─ desktop: invoke('db_query' …) ─► rusqlite
评分 / 选题 / 量表 / AI 提示词：@mindscope/core（纯函数）
平台差异（备份、PDF、文件夹、AI、日志）：Platform 接口（src/platform/types.ts）
```

- `SqlDriver` 只有 `query` / `execute` / `batch` 三个方法，所以**所有 SQL 都在 `packages/storage` 里**，两端执行完全相同的语句，可以在 Node 里单测。
- `Platform` 由 `createPlatform()` 按运行环境动态加载，另一端的代码不会被打进包里。
- 网页的数据库在 Worker 里，用 `opfs-sahpool`；另一个标签页占用时报 `OPFS_LOCKED`，界面会提示。

### 迁移规则

- 迁移在 `packages/storage/src/migrations/`，**只能追加**，已发布的迁移不能修改（启动时校验 FNV-1a 校验和，改动会报错）。
- 桌面版在执行迁移前自动备份到 `data/backups/…-pre-migration-vN.db`。
- 新增迁移：新建 `000N_name.ts` 导出 `sql`，加入 `migrations/index.ts`，在 `packages/storage/test/migrate.test.ts` 覆盖，并在发布测试中确认旧版本数据能升级（`npm run test:release` 第 6 项会自动对 `release/` 下每个旧版本做升级测试）。

## 6. 评分方法

### 16 型人格：`bipolar-likert@1`

- 每题 7 级：`xᵢ = (rᵢ − 4) / 3`，范围 −1 到 +1；反向题 `keyᵢ = −1`。
- 维度得分 `S = Σ wᵢ·keyᵢ·xᵢ / Σ wᵢ`，标准误 `SE = √(Σw(v−S)²/Σw ÷ (n_eff−1))`。
- 清晰度按 |S| 分档：≤ 0.1 接近均衡（字母显示 `X`）、0.3、0.6；有效作答不足 `minAnsweredRatio` 时显示 `?`。
- 八功能独立计分：`F = 50 + 50 × 平均值`（0–100），相对强度 `F − 八项平均`；题数少于 `minFunctionItems` 不显示。
- 理论功能栈（Grant / Beebe）只作参照，并与实测最强两项对比（match / partial / mismatch）。

### 自适应选题

- 每次选"最不确定"的维度：`U_d = SE / max(|S|, 0.05)`，先经过若干热身轮；功能题均匀穿插；全域模式轮流出题。
- 随机数用 mulberry32 + 会话种子，**同样的答案得到同样的题序**。
- `packages/core/test/simulation.test.ts` 用模拟答题者验证：快速 / 普通 / 资深模式的类型还原率约 95% / 98% / 99%。

### 大五人格：`likert-mean@1`

- 题库 `ipip-b5`：一个题目池 + 三个模式（quick = Mini-IPIP 20、normal = IPIP 50 题标记、senior = IPIP-NEO-120）。**维度、子维度和计分方向按模式分别记录**，因为同一句题目在不同量表中可能属于不同维度（"Feel others' emotions" 在 50 题版属宜人性，在 120 题版属开放性 O3）。
- 计分：每题 1–5，反向题 6 − x；维度 / 子维度分 = 平均分，0–100 = (平均分 − 1) ÷ 4 × 100，附标准误；作答不足 75% 的维度不计分。粗分档按量表三等分（2.33 / 3.67），**不是常模**。
- 存储：表结构只允许 `personality` / `wellbeing` 两类工具，大五作为 `personality` 存储，用计分引擎区分（`json_extract(v.scoring_json, '$.engine') LIKE 'likert-mean@%'`，见 `repositories/bigfive.ts` 的 `IS_BIGFIVE`）；16 型的所有查询排除它。
- 答题复用 16 型的答题页：`BigFiveRepository.asBank()` 把一个模式转成答题页使用的题库视图；会话一开始就包含整个题目列表，到最后一题即进入核对。
- 修改译文或题目：编辑 `generate.py` 并**另存为新版本号**的 JSON（已发布版本不可变）；`packages/banks/test/bigfive.test.ts` 会核对三个模式的题数、子维度结构、Mini-IPIP 与 50 题版计分键的一致性，以及官方计分键抽查。

### 心理量表：`sum@1`

- 原始分 = Σ 选项值（反向题取反），得分 = 原始分 × 乘数（WHO-5 为 4）。
- 分级区间必须覆盖每一个可能的分数且不重叠（`validateScale` 检查）。
- 安全题（PHQ-9 第 9 题 ≥ 1）独立于总分判断。

## 7. 添加或修改题库 / 量表

**题库版本不可变**：已安装的版本按 `instrument@version` 和内容哈希存储；同一版本号内容变了会报 `BankIntegrityError`。修改题目必须发布新版本号，旧结果始终用作答时的版本解释。

新增 16 型题库版本：
1. 复制 `packages/banks/ms16/bank-0.1.0.json` 为新版本，修改题目（题目 id 永不复用）。
2. 用 `validateBank` 校验（`packages/banks/test` 会自动跑）。
3. 在 `packages/banks/src/index.ts` 的 `BUILTIN_BANKS` 里加入。

新增心理量表：
1. 在 `packages/banks/wellbeing/` 写 JSON（题目、选项、计分、分级、安全题、`source` / `licenseNote` / `citation` 必填）。
2. 分级必须来自可引用的官方资料；自编量表设 `status: "experimental"`，界面会标注"非标准化"。
3. 加入 `WELLBEING_SCALES`，在 `packages/banks/test/wellbeing.test.ts` 写边界值测试。
4. 在 `NOTICE.md` 写明许可。**不要加入许可不明确的量表**（例如 DASS 不允许在公开应用中显示分数）。

## 8. 界面文案（i18n）

- `src/i18n/zh-CN.ts` 与 `en.ts` 必须有完全相同的键；`src/i18n/messages.test.ts` 会检查键、占位符一致，以及不含 vue-i18n 的特殊字符 `|` 和 `@`。
- 文案里不要用花括号表示字面量（会被当成占位符）；键名不要含 `-`。

## 9. PDF 与打印

- 桌面版用 WebView2 原生 `PrintToPdf`，系统字体渲染中文，图表是矢量 SVG。
- 打印样式：`.ms-no-print` / `.ms-print-only`；图表、卡片避免跨页；正式报告页（`ReportPage.vue`）用命名页面 `@page report-zh / report-en` 的边距盒子打印页码和页脚。
- `/diagnostics/pdf` 是 PDF 测试页。

## 10. 可选 AI

```
core/ai/prompt.ts   buildAiRequest()：按任务和用户勾选的数据类别生成消息；输入类型里没有姓名/备注/答案字段
src/ai/             设置、错误文案、安全 Markdown（只输出固定标签）
platform AiBridge   desktop → Rust；测试构建 → 本机模拟（simulatedAi.ts）
src-tauri/ai.rs     读设置（地址/模型不接受前端临时传入）→ 校验地址 → 取 Key → 流式请求 → 记录 network_audit
```

- 地址规则：只允许 `https://`；`http://` 只允许 `localhost` / `127.0.0.1` / `[::1]`。
- 错误统一为 `{ code, status, message }`，message 中的 Key 会被替换为 `[key]`。
- 新增服务商：只要是 OpenAI 兼容的 `/chat/completions`（SSE），在 `src/ai/config.ts` 的 `AI_PROVIDERS` 加预设即可。
- 修改提示词时提升 `AI_PROMPT_VERSION`，已保存的 AI 内容会记录它们用的版本。

## 11. 隐私与安全约束（改代码时请保持）

- **CSP**：网页构建在 `vite.config.ts` 注入 `connect-src 'self'` 等策略；桌面版在 `tauri.conf.json`。不要放宽。
- **日志**：只记事件和错误，不记答题内容、人物资料、AI 内容和 Key。
- **网络**：任何新的对外请求都必须 (1) 由用户触发并确认，(2) 写入 `network_audit`。
- **文件**：桌面版只能写数据根目录；新增文件请放进 `AppPaths` 已有的目录。
- **危险操作**（删除、清理、恢复、覆盖）都要二次确认；桌面版删除和恢复前自动备份。
- `npm run build` 结束时会运行 `scripts/verify-dist.mjs`，确保测试专用代码（模拟 AI）没有进入正式构建。

## 13. 发布流程

1. 改版本号（三处保持一致）：`apps/mindscope/src-tauri/Cargo.toml`、`apps/mindscope/src-tauri/tauri.conf.json`、`packages/core/src/index.ts` 的 `APP_VERSION`。
2. `npm run typecheck && npm test && npm run test:rust && npm run test:e2e && npm run test:e2e:release`
3. `npm run package:portable`、`npm run package:web`
4. `npm run test:release`
5. 更新 `CHANGELOG.md`、`README.md`、`docs/PROGRESS.md`。
6. 发布 `release/` 下的两个 zip，附上 `.build/checksums/` 中对应的 SHA256。

**文件夹约定**（`release/` 与 `.build/` 都不进 git）：

| 位置 | 内容 |
|---|---|
| `release/` | 各版本的便携版和网页版 zip；`release/MindScope/` 是最新版（`MindScope.exe` + `LICENSE.txt`），打包时只替换这两个文件，在里面运行产生的数据会保留 |
| `.build/staging/` | 打包用的临时文件夹，每次重建 |
| `.build/checksums/` | 每个 zip 的 SHA256 |
| `.build/old-release-folders/` | 旧版本解压并运行过的文件夹（含测试数据），供发布测试第 6 项做升级测试 |

便携版打包会检查 zip 里只有 `MindScope.exe` 和 `LICENSE.txt`，否则中止。

PowerShell 脚本用**带 BOM 的 UTF-8** 保存：Windows PowerShell 5 会把无 BOM 的文件按系统代码页读取，导致中文和符号乱码。

## 14. 约定

- 评分、数据库、界面分开：评分在 core，SQL 在 storage，页面里不写 SQL。
- 新功能先写纯函数和单元测试，再接界面；关键流程补 E2E。
- 不用假数据冒充真实结果；示例数据必须 `is_demo = 1` 并在界面上标注。
- 注释写"为什么"，简短。
